# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выходят только для последнего релиза.
Обновиться можно из окна «Настройки» (автообновление) или вручную из [Releases](https://github.com/andfriden/YaMusic/releases).

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Используйте приватную форму:

1. Откройте вкладку [Security](https://github.com/andfriden/YaMusic/security)
2. Нажмите **Report a vulnerability** (GitHub Security Advisories)

В отчёте укажите: версию и ОС, шаги воспроизведения, что позволяет сделать уязвимость, и, если есть, предложение по исправлению.

## Что считается уязвимостью

- утечка OAuth-токенов: в логах, отчётах о падении, файлах на диске
- возможность выполнить чужой код через скачанный файл, текст песни, ответ API или `.m3u`-очередь
- обход проверок при обновлении (подмена сборки, небезопасная загрузка пакета)
- чтение файлов вне каталога «Загрузки» при скачивании трека
- утечка данных об аккаунте третьим сторонам

## Что не считается

- ограничения самого API Яндекс Музыки (например, прослушивания из неофициального клиента не попадают в историю аккаунта)
- ошибки авторизации из-за неверного или просроченного токена
- отсутствие функций из ROADMAP.md

## Что делать, если токен утёк

Токен даёт доступ к аккаунту Яндекса в рамках выданных прав. Немедленно:

1. Отзовите доступ приложения в настройках Яндекс ID: «Безопасность» → «Сторонние приложения»
2. Удалите сохранённый токен из YaMusic (выйдите из аккаунта) и авторизуйтесь заново
3. Если ссылка или лог опубликованы — удалите их; при утечке в issue напишите мейнтейнеру

## Раскрытие

После исправления информация публикуется в Security Advisory и в CHANGELOG.md с указанием версии с фиксом.
